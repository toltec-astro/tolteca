# KIDs model reports and timestream solving

## Scope and ownership

`ModelFit` produces a channel-oriented `kids_model.ecsv` report for each fitted
sweep block. Python and native fitting backends share the report and flag
contracts. They can fit different numerical models; the report identifies the
model that was fitted. A consumer must support that model explicitly.

The resolved raw observation context selects the recorded calibration sweep,
its fitted realization and the destination acquisition block. Stub preparation
packages that selection without fitting again. The acquisition remains the base
file. A stub is applied only when the context selects it as an override or default.

Timestream **solving** maps acquired I/Q to detector response variables `r` and
`x`. Fitting estimates the calibration from sweep measurements. Transporting a
report does not establish that its calibration is scientifically acceptable.

## Channel rows and complete models

Each report has one row per acquired channel, in acquisition order. `chan` is
an integer channel identity within one readout network. `f_in` is the acquired
probe frequency in Hz. `f_out` is a fitted output frequency, when available;
it does not replace the probe frequency. `flag` contains the common fit flags.
Unfitted and rejected channels retain their rows and explicit flags.

Table metadata contains `schema: kids.fit/1`, the model name and versioned
parameter schema, source observation and block, source I/Q accumulation length,
flag definitions, quality thresholds and the declared nonlinear branch.
Column units must agree with the model schema.

Independent physical models retain the fitted affine or delay gain coefficients,
resonance frequency, loss, complex coupling and drive nonlinearity. They include
the fitted `a_nl` and the fixed-drive coefficient `b = 2*a_nl*r_reference^3`.
Zero drive nonlinearity is an explicit model value.

Selected joint groups are stored in `meta.joint_models`, with schema
`kids.joint/1`. A group carries:

| Field | Meaning and ordering |
| --- | --- |
| `group_id`, `resonator_ids` | Calibration-scoped identities; no implicit primary resonator |
| `channels`, `probes` | Acquired channel identities and probe frequencies, in matching order |
| `fr`, `r`, `a_nl` | Reference resonance frequency, loss and nonlinearity, per resonator |
| `gain_family`, `gain_model` | Full affine or delay gain coefficients, per channel |
| `coupling_re`, `coupling_im` | Complex coupling matrix, channel × resonator |
| `nonlinear_branch` | `unique`, `increasing` or `decreasing` stationary response |
| `iq_covariance`, `noise_source` | I/Q weights in model units, all I followed by all Q |
| `fit_flag`, `rank_rtol`, `condition_max` | Group quality and numerical qualification |

The number of resonators can differ between groups. Affine gain retains `f_g`,
`H0_re`, `H0_im`, `H1_re`, `H1_im`. Delay gain retains `f_g`, `H0_re`, `H0_im`,
`gain_a`, `tau`. Consumers evaluate the gain at the recorded probes. They must
not replace the full group with an effective independent channel model.

## ECSV-to-stub representation

The model-header variable pair is an atomic override/default group:

| NetCDF entity | Content |
| --- | --- |
| `Header.Toltec.ModelParams[block, column, channel]` | Numeric table cells |
| `Header.Toltec.ModelParamsHeader[column, character]` | Column names |
| `ModelParams:ecsv_header_<block>` | Complete ECSV header and column-name line for that block, with no data rows |

`ecsv_header_<block>` is generated by the ECSV writer from the empty table
template. It retains column order, types, units, descriptions and table metadata,
including arbitrary nested joint models. The transport does not extract or
re-serialize selected model fields. Numeric columns are scalar and unmasked;
integers must fit exactly in float64. Unsupported columns or inconsistent axes
raise before writing. The reader restores each column's declared numeric type.

Different slots can have different table columns. The shared name axis is their
union; each slot's ECSV header identifies the columns belonging to that report.
Replacing a slot preserves other slots. An already-selected block retains its
original block identifier when decoding the attribute.

The source accumulation length is the ECSV metadata value
`Header.Toltec.AccumLen`. It is not a separate model-header variable and does
not override the destination acquisition's accumulation length. Solving divides
destination I/Q by `destination_accumlen / model_accumlen`.

Native ECSV and stub readers use the same model-report parser after reconstructing
the table. Production headers without an ECSV attribute retain their historical
GainLinTrend interpretation. Superseded development descriptor attributes are
not another supported report format.

## Common fit flags

`ModelFitFlag` in Python and `FitFlag` in Kidscpp define the same uint32 bits.
Every report records their names and values. Fit flags describe the source model;
sample flags describe an attempted solution.

| Flag | Required consumer behavior |
| --- | --- |
| `fit_unusable` (bit 13) | Do not produce a valid solution from this model |
| `fit_joint_required` (bit 22) | Use the selected complete group; suppress independent channel solving |
| Quality warnings, including `fit_at_bound` | Preserve the warning and numerical result unless a separate unusable flag vetoes it |

`fit_joint_required` alone is not an unusable fit. Missing joint information must
not lead to an independent-row fallback. An unusable group retains its model
and diagnostics, with flagged NaN solutions. Zero flags do not certify scientific
acceptance. Bits 10 and 23 are reserved; consumer capability is not a fit-quality
flag. Unsupported model schemas raise explicitly.

## Nonlinear fixed-drive solving

For channel `k` and resonator `j`, the response is

```text
z_k = H_k(f_probe,k) [1 − Σ_j c_kj / (r_j + i x_effective,kj)]
x_0,kj = f_probe,k / f_res,j − 1
x_effective,kj = x_0,kj + b_j / (r_j² + x_effective,kj²)
b_j = 2 a_nl,j r_reference,j³
```

Gain, coupling, probe frequencies and `b` remain fixed during solving. Loss and
intrinsic resonance frequency vary. Thus `a_nl = b/(2*r³)` varies with loss;
holding fitted `a_nl` constant would change the assumed drive power.

The response Jacobian includes the implicit detuning derivatives at fixed `b`,
including the loss derivative. Returned `x` is intrinsic detuning `x_0`, indexed
by channel and resonator. The report's original resonator identities are retained.

The `unique` branch is qualified for `0 <= a_nl <= 0.75`. The directional branches
select the stable quasistatic response reached from increasing or decreasing
frequency. They do not infer an arbitrary hysteretic time history. Derivatives
are local to a stable branch and do not describe jumps between branches.

Positive physical state, finite values and sufficient response rank are required.
Failed solutions remain flagged NaNs. No zero-nonlinearity or independent-model
fallback is permitted. Covariance is conditional on the calibration and supplied
I/Q weights; unit weights must not be described as measured readout noise.

Python supports additional bounded starts and ambiguity/continuation diagnostics.
The native solver also tests independent loss/frequency starts and rejects
competing solutions with squared whitened-residual differences at most 9 and
local noise-scaled state separation greater than 5, matching the Python defaults.
Agreement on accepted trajectories does not establish identical global search policies or
scientific acceptance of a measured timestream. Citlali uses the native solver
and retains its fit, sample and group diagnostics.

## Verification

Required checks cover complete table/metadata round trips, independent block
slots, unknown numeric columns, malformed transport, shared flag values, joint
routing and unusable-model vetoes. Numerical checks compare the fixed-drive
Jacobian against finite differences and stationary roots against an independent
cubic calculation, including declared directional branches.

The real Tune comparison fits both 145609 blocks with Python, then compares
ECSV and stub consumption in Python and native solving using controlled I/Q
trajectories. Measured-timestream application is a separate check: only the
recorded final Tune block calibrates the following acquisition. Reports must
distinguish fit quality, controlled numerical parity and measured-data acceptance.
