# Differentiate frequency sweeps

Use `D21Analysis` to compute the complex derivative `dS21/df` on the measured grid
and a channel-averaged derivative magnitude on a common frequency grid.

## Prepare a sweep

| Requirement | What to supply |
| --- | --- |
| Signals | I/Q transmission, shape `(sample,)` or `(chan, sample)` |
| Frequency | Quantity with the full I/Q shape; samples on the last axis |
| Grid | Increasing frequencies; multi-channel sweeps share sample spacing |
| Savitzky–Golay | Uniform spacing and at least `smooth` samples |
| Unified output | Enough samples remain after excluding both channel edges |

The analysis accepts NumPy-backed and Dask-backed sweeps and evaluates signal
and frequency arrays eagerly. Keep source files open until the call completes.
Validate acquisition continuity and
frequency ordering before analysis; a sweep view does not check these properties.

```{testcode}
import numpy as np
import xarray as xr
from astropy import units as u
from tolteca_kidsproc.accessors import make_kids_dataset
from tolteca_kidsproc.analysis import D21Analysis

frequency = np.linspace(1e9, 1.1e9, 101)
signal = 1 / (1 + 1j * (frequency - 1.05e9) / 1e6)
source = make_kids_dataset(signal.real, signal.imag, frequency=frequency * u.Hz)
analysis = D21Analysis(method="gradient", smooth=5, exclude_edge=5)
result = analysis(source.kids.sweep)
view = result.kids.d21
assert view.d21.shape == source.I.shape
assert view.d21_analysis == analysis
assert view.d21_unified.shape == view.f_unified.shape == view.cov_unified.shape
```

The same call accepts chunked data:

```{testcode}
chunked = source.chunk({dim: 32 for dim in source.dims})
from_chunks = analysis(chunked.kids.sweep)
xr.testing.assert_equal(from_chunks.kids.d21.d21_unified, view.d21_unified)
```

## Choose an estimator and grid

| Setting | Use |
| --- | --- |
| `method="savgol"` | Quadratic Savitzky–Golay derivative; `smooth >= 3` |
| `method="gradient"` | Numerical gradient with optional uniform-filter smoothing |
| `smooth=0` or `None` | Disable smoothing with the gradient method |
| `exclude_edge` | Drop this many samples from each channel edge for unified interpolation; omitted uses `smooth` |
| `f_lims=(low, high)` | Set common-grid bounds as frequency quantities; high is excluded |
| `f_step` | Set positive common-grid spacing as a frequency quantity |
| `resample` | Positive integer divisor of measured spacing when `f_step` is omitted |

Use finite, increasing bounds and positive spacing. The generated
{ref}`configuration reference <kidsproc-analysis-models>` lists defaults, field types,
validators, and serialized schemas. Estimator details are described by
[SciPy's Savitzky–Golay reference](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.savgol_filter.html).

## Read results

| Property on `result.kids.d21` | Meaning | Units |
| --- | --- | --- |
| `d21` | Complex derivative, preserving input dimensions and coordinates | `Hz^-1` |
| `d21_unified` | Mean of interpolated derivative magnitudes from contributing channels | `Hz^-1` |
| `f_unified` | Common frequency grid | Hz |
| `cov_unified` | Contributing channel count at each frequency | Count |
| `d21_analysis` | Producing configuration | — |

D21 labels derivatives as `Hz^-1` and does not propagate input signal units.
When interpreting unit-bearing I/Q, account for those signal units separately.

Bins without contributing channels have zero magnitude and zero coverage. Use
`cov_unified > 0` when selecting measured portions of the common grid.

```{testcode}
measured = view.d21_unified.where(view.cov_unified > 0, drop=True)
assert measured.size > 0

# Compute standalone arrays when no result tree is needed.
matched = analysis.make_matched(source.kids.sweep)
unified = analysis.make_unified(source.kids.sweep)
np.testing.assert_allclose(matched, view.d21)
np.testing.assert_allclose(unified, view.d21_unified)
```

## Compute directly from numerical arrays

Use the classmethods for NumPy arrays with all numerical settings supplied
explicitly. They return arrays and leave the inputs unchanged. Frequencies are
plain values in Hz; use the instance methods above when working with sweep views
and quantity-aware configuration.

```{testcode}
f = source.kids.sweep.frequency.u.to(u.Hz).values
s21 = source.kids.sweep.S21.values
d21 = D21Analysis.compute_matched(s21, f, smooth=5, method="gradient")
f_common, magnitude, coverage = D21Analysis.compute_unified(
    d21, f, f_lims=(float(f.min()), float(f.max())),
    f_step=float(f[1] - f[0]), exclude_edge=5,
)
np.testing.assert_array_equal(d21, matched.values)
np.testing.assert_array_equal(magnitude, unified.values)
np.testing.assert_array_equal(f_common, unified.f_unified.values)
np.testing.assert_array_equal(coverage, unified.cov_unified.values)
```

## Store results in an observation tree

1. Select the input sweep view from the desired observation block.
2. Pass that block as `output`, or select a destination with `parent_namespace`.
3. Read the analysis view from the destination block.

```{testcode}
import xarray as xr

observations = xr.DataTree.from_dict({"scan/sweep": source})
returned = analysis(
    observations["scan"].kids.sweep,
    output=observations,
    parent_namespace="scan",
)
assert returned is observations
np.testing.assert_allclose(observations["scan"].kids.d21.d21, matched)
```

By default, results occupy `tolteca_kidsproc.analysis.d21/{d21,d21_unified}`
under the destination. The analysis stores its configuration on that namespace.
Supplying `output` writes results there without copying the input and returns the
supplied tree; omitting `output` returns a new tree with `_input`.

Existing results are reused when the configuration and required outputs match.
Input values and coordinates are **not compared**. After editing or replacing
input, pass `force=True`, then reacquire `destination.kids.d21`. Relative parent
paths start at `output`; absolute paths start at its root. A selected parent must
exist, and `parent_namespace` requires an explicit output tree.
